Hologram retrieval

A phase-only hologram is found by bouncing a wavefront between the hologram plane and the image plane, keeping only the amplitude each plane actually knows and carrying the phase forward. This is a reduced, 8-sample version of the Gerchberg–Saxton loop — small enough to watch every wave change on every pass, and to see it as an actual wave in time, not just a vector. Every FFT here runs in Python on this same server, via /api/holo/*.

Ready
  1. Propagate the current hologram guess to the image plane (Fourier transform).
  2. Match brightness: swap in the target image's amplitude, keep the phase just computed.
  3. Propagate back to the hologram plane (inverse Fourier transform).
  4. Match illumination: flatten the amplitude to the laser's uniform intensity, keep the phase.

Model: 8 unit-amplitude samples at the hologram plane, related to the image plane by an 8-point discrete Fourier transform. An uploaded image is reduced to 8 raw brightness values in the browser (plain pixel sampling, not FFT work) — everything past that, including normalization and every iteration, runs in Python (numpy.fft.fft / ifft, in epicycle/holography.py) behind POST /api/holo/target, /api/holo/step, and /api/holo/reset.

Fourier hologram generator

Upload an image, type a word, or pick a shape, and the Gerchberg–Saxton algorithm searches for a phase‑only hologram that reconstructs it. Every FFT runs in Python on the server (numpy.fft.fft2 / ifft2), not in the browser — the page just asks for images and displays them. This is the same principle behind spatial light modulators used in real holographic displays and optical trapping.

How this hologram is actually used with a laser

The optical path the computed pattern is built for — light only ever travels forward along it

The GS loop above runs once, in Python, to design the pattern — the “propagate back” step is only arithmetic, standing in for what the lens would show if light could run in reverse. On the bench, the pattern is loaded onto a phase‑only spatial light modulator (SLM): each gray level in the hologram panel tells one pixel of the SLM how much to delay the light passing through it, from 0 up to a full 2π cycle. A collimated laser illuminates the SLM, a lens performs a genuine optical Fourier transform of the modulated wavefront, and the reconstructed image appears in that lens's focal plane — on a screen, or on a camera sensor, exactly like the simulated panel above.

Architecture: this tool holds no FFT code at all — every “Step” click sends the session id to POST /api/gsgen/step, a Flask process runs one Gerchberg–Saxton pass with numpy.fft.fft2/ifft2, and returns two PNGs plus a correlation number. “Match” is a correlation, not a pixel-exact score — phase-only holograms rarely reach a perfect one. Backend: epicycle/gs_hologram.py.

Animated hologram

The Epicycle drawing tool on the Photography page turns one photo into a curve that moves through time. This is the holography counterpart: instead of one static target image, a real 2‑D Gerchberg‑Saxton loop runs against a short sequence of target frames — simple shapes drawn frame by frame — converging a fresh phase-only hologram for each one. Playing the frames back shows an actual reconstructed picture changing over time, the same principle behind real time‑multiplexed holographic video.

Each frame's target is one of four shapes (a moving dot, a growing ring, a rotating bar, or a pulsing blob), drawn with OpenCV in epicycle/holo_animate.py and softened so it fits the FFT grid cleanly, then converged with the real 2‑D engine in epicycle/holography2d.py (numpy.fft.fft2 / ifft2). The whole sequence — every frame's target, phase and reconstruction image — comes back from one call to POST /api/holo2d/anim/build; the browser only plays it back.
